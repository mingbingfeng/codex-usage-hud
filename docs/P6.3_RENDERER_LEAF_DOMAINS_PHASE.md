## Result

The fixed P6.3 migration order is now represented directly in the asset
manifest:

```text
model_picker -> theme -> diagnostics -> budget -> rest_reminder -> session_view
```

Each owner implements `install/apply/dispose`, registers through the P6.2
kernel, and is joined into the existing single IIFE before the remaining legacy
fragments. Payload routing still applies domains in the frozen order:

```text
currentSession -> sessionSwitch -> budget -> settings -> overlay ->
backgroundUsage -> diagnostics -> usageInsights -> sessionCleanup
```

The owner map is:

| Owner | Lines | Moved responsibility |
|---|---:|---|
| `model_picker.py` | 251 | Catalog model/reasoning injection and delegated selection lifecycle |
| `theme.py` | 293 | Theme token apply, storage snapshot, binding report, observer lifecycle |
| `diagnostics.py` | 139 | DEBUG runtime-error panel and connection-health projection |
| `budget.py` | 332 | Progress rails, overflow layout, badge fitting, budget payload apply |
| `rest_reminder.py` | 311 | Toast/bubble markup, countdown ticker, positioning, reminder apply |
| `session_view.py` | 638 | Session/request text, numeric animation, rows, activity/details, session apply |

The implementations above no longer remain in the continuous legacy fragments.
Small explicit compatibility exports remain where unmigrated layout/settings
handlers still call a leaf capability. Cross-leaf calls use the registered
owner contract, for example session view delegates progress and connection
health to the budget and diagnostics owners.
