# Privacy Policy for codex-usage-hud

`codex-usage-hud` 的首要原则是 `local-first privacy`。这个项目的职责，是在你的机器上读取本地可访问的 Codex 使用记录，并在本地完成解析、统计与显示。默认仍是只读分析器；“存储”页的写操作必须由用户显式启用并完成 dry-run 与二次确认。

## 核心承诺

- 只在本地运行。
- 只读本地日志与本地数据库；显式启用的本地文件管理写操作是单独列出的例外。
- 绝对不联网。
- 绝对不上传任何内容。
- 绝对不把 prompt、response、token 统计、路径信息或元数据发送给作者、维护者或任何第三方。

如果某个未来改动违反以上原则，那就不再符合本项目的设计目标。

## 数据来源边界

本项目预期只会接触以下类型的本地数据源：

- 本地 JSONL 日志文件
- 本地 SQLite 数据库

这些数据源的处理目标仅限于：

- 读取
- 解析
- 聚合
- 计算本地 HUD 所需指标
- 在本地终端显示结果

本项目不应主动修改这些原始数据源，也不应把它们复制到远端位置。存储管理器不会 raw 修改原始 JSONL、SQLite、WAL/SHM、凭据、配置或未知项；会话、插件和登录状态只通过用户确认的官方 Codex 动作处理。

## 显式本地文件管理例外

设置里的“存储”页只有在用户点击扫描、预览和确认后才会访问对应的本地元数据。renderer payload 只包含中性的根标签、相对路径、分类、大小、mtime、风险和操作状态，不包含 prompt、response、token、凭据或文件内容。

raw 清理第一版仅允许过期且未被配置引用的临时 staging/clone 项，并在执行前按 inventory revision、canonical path、lstat 指纹和锁定状态重新验证。Codex、app-server 或插件同步运行时，操作只会排队到退出后；HUD 不会自动杀进程。SQLite 主库与 `-wal`/`-shm` 是不可拆分的受保护组。未知文件、symlink/junction/reparse point、`auth.json`、`config.toml`、`secrets`、会话 transcript 和活动插件 cache 默认禁止 raw 删除。

## 我们绝不会做的事

- 不发起网络请求
- 不上传日志
- 不上传数据库
- 不上传 prompt 或 response
- 不接入遥测、埋点、分析 SDK
- 不收集设备指纹
- 不收集使用者身份信息
- 不自动创建 issue 附件
- 不自动把诊断信息同步到云端

## 对 Issue / Bug Report 的严厉警告

## 不要上传原始日志

如果你在 GitHub Issue、讨论区、聊天工具、邮件或任何公开/半公开渠道反馈问题，**千万不要上传原始 JSONL 日志、原始 SQLite 数据库，或未脱敏的会话片段。**

原因很简单：

- 原始日志里可能包含 prompt
- 原始日志里可能包含 response
- 原始日志里可能包含文件路径、项目名、内部代号
- 原始日志里可能包含 token 统计与时间线
- 原始日志里可能暴露你的工作内容、客户信息或私有代码上下文

一旦公开，后果往往不可逆。

## 安全反馈建议

如果你需要报告问题，请优先采用以下方式：

- 只提供最小化、手工脱敏后的片段
- 删除或替换 prompt、response、文件路径、项目名、用户名、邮箱、主机名
- 如果只需要复现结构问题，优先自行构造虚拟样例数据
- 在不影响复现的前提下，尽量只描述字段形状，而不是贴出完整原文

可以把敏感字段替换成下面这种形式：

```text
prompt: [REDACTED]
response: [REDACTED]
path: C:/[REDACTED]/project
user: [REDACTED]
```

## 本地优先意味着什么

在这个项目里，`local-first` 不只是一个口号，而是工程边界：

- 所有解析在本地完成
- 所有计算在本地完成
- 所有显示在本地完成
- 默认假设日志高度敏感
- 默认假设用户不希望任何外发

## 信任模型

请把本项目视为一个“本地只读分析器”，而不是“云服务客户端”。

如果你在代码中发现任何会联网、会上传、会收集遥测、会自动分享数据的行为，那应该被视为严重偏离设计目标的问题，并应立即报告。
