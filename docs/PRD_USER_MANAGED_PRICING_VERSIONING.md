# PRD：用户维护单价与后续请求计费

- **状态**：已实现，历史重算与普通会话全量快照已移除
- **提出日期**：2026-08-05
- **适用模块**：Renderer HUD 设置、价格配置、会话用量统计、后台用量统计
- **目标版本**：下一次价格配置功能迭代

## 1. 背景与目标

HUD 的单价必须由用户自己维护。用户修改单价后，新的单价只应影响保存之后产生的请求；已经展示或已经统计的历史费用不应因为设置页保存而被重新扫描、重算或改写。价格版本仍然保留，用于 provider/模型匹配、配置导入导出和价格变更追溯。

本需求解决两件事：

1. 改价确认时记录当前时间，新价格从该时刻起用于后续请求。
2. 让用户可以直接导出当前价格 JSON，并获得带字段说明的空模板，能够在外部编辑后导入。

## 2. 用户故事

- 作为用户，我修改某个模型单价后，希望系统明确提示新价格只对后续请求生效。
- 作为用户，我希望修改单价不会触发历史会话的全量扫描，也不会改变已经看到的历史费用。
- 作为用户，我导出价格表后，希望导出的 JSON 能再次导入，并保留 provider、模型匹配规则和缓存价格。
- 作为用户，我没有现成 JSON 时，希望下载一个空模板，照字段填写即可。
- 作为用户，我填错价格或时间时，希望导入失败且现有价格不受影响。

## 3. 范围

### 包含

- Renderer 设置页的价格编辑、批量改价、导入、导出、空模板下载。
- 全局价格表和 provider 价格表的生效时间管理。
- 普通会话、CLI 会话和后台请求按请求发生时间选择价格版本。
- 价格版本和价格变更审计的持久化、查询和导入导出。
- 已有后台请求的计费结果保持稳定；新后台请求按新价格计算。
- 迁移现有配置并保证旧数据可读。

### 不包含

- 自动抓取或自动判断官方价格。
- 外币换算、订阅额度折算、税费和服务层级（Standard/Fast）新规则。
- 历史费用重算、影响预览和历史计费审计。
- 普通会话请求级的全量价格快照账本；旧的 `pricing-snapshots.sqlite3` 文件不删除，但运行时不再创建、读取或写入。
- Qt/Tk 新产品功能；实现必须位于 Renderer/CDP 路径。

## 4. 术语与核心规则

### 4.1 生效时间

界面文案使用 **“保存后对后续请求生效”**，辅助说明为：**“确认保存时记录当前时间；已有记录保持原来的统计结果。”**

- 普通设置页改价的 `effective_at` 由服务端在确认保存时生成，使用当前 UTC 时间；用户不能预约未来时间，也不需要填写时间控件。
- 时间必须带时区并存储为 UTC 时间戳；展示使用系统本地时区。
- 边界采用左闭右开：`occurred_at < effective_at` 使用旧价格，`occurred_at >= effective_at` 使用新价格。
- 按请求/事件发生时间判断，不按文件修改时间、HUD 启动时间或设置保存后的历史扫描时间判断。
- 价格 JSON 导入保留条目中明确提供的 `effective_at`，这是显式导入版本数据的行为；普通手工改价不提供历史生效时间入口。

### 4.2 价格版本

每次确认改价生成一个不可变版本：

- `version_id`：唯一 ID。
- `provider`、模型匹配字段（`model`/`model_pattern`、`base_url`）。
- `input`、`cached_input`、`cache_write`、`output`、`reasoning`，单位均为 USD/1M tokens。
- `effective_at`、`created_at`、`created_by`（`user_import`、`user_edit`、`builtin_migration`）。
- `source` 可选为 `manual`、`import`、`builtin`；不代表官方认证。

同一 provider + 模型匹配范围不得存在相同 `effective_at` 的两个版本。若冲突，后保存的版本覆盖前一个版本，但必须保留版本 ID 和审计记录，不能产生不确定匹配。

### 4.3 计价选择

对每条用量：

1. 先按 provider、base URL、模型匹配优先级解析价格范围。
2. 在该范围内选择 `effective_at <= occurred_at` 的最新版本。
3. 找不到历史版本时，使用现有内置价格作为离线兜底，并把费用标记为 `fallback`；不得把当前新价格倒灌到更早用量。
4. 找到价格后使用该版本计算请求费用；价格版本本身由不可变版本表维护，避免在普通会话中复制完整价格 JSON。保存新价格不会遍历或改写已有请求。
5. 未知模型或缺少必要价格字段时，费用为 `unavailable`，不显示为 `$0`。

普通会话不创建请求级价格快照账本。保存价格时不执行历史影响预览、不重建汇总缓存、不触发后台全量扫描；只有后续 JSONL/后台数据变化时才解析新增请求。旧快照数据库即使存在，也不参与启动和计价。

后台请求仍在其自身的用量表中保存已计算费用和必要的价格状态，保证后台历史聚合不因配置刷新而漂移；这不是普通会话全量快照，也不提供历史重算入口。旧后台重算表和字段仅为 SQLite 兼容保留，不再写入。

费用公式沿用现有语义：

```text
billable_input = input_tokens - cached_input_tokens - cache_write_tokens
cost = billable_input * input_price
      + cached_input_tokens * cached_input_price
      + cache_write_tokens * cache_write_price
      + output_tokens * output_price
```

均除以 1,000,000；`output_tokens` 已包含 reasoning output 时不得重复计费。

## 5. 交互设计

### 5.1 改价确认弹窗

触发：用户在设置页修改任意模型价格并点击“保存价格”、导入新价格或批量覆盖。

弹窗内容：

- 标题：**“保存新价格”**。
- 明确提示：**“确认保存时记录当前时间；新价格从此时起用于后续请求，已有记录不进行历史重算。”**
- 变更摘要：模型/provider、旧价格、新价格。
- 操作：`取消`、`确认并保存`。

确认前校验：价格必须是非负有限数字，至少包含 input 和 output；保存失败时不改变现有配置。

### 5.2 历史显示与价格变更审计

- 保存新版本后，不修改已有记录的 `cost_usd`，不创建普通会话价格快照，也不生成历史影响预览。
- 保存后产生的新请求按 provider、base URL、模型和请求时间选择新价格版本。
- `pricing_audit` 只记录价格版本的新增、替换和迁移，不记录每条历史费用，也不支持费用重算审计。
- 设置页可以展示当前价格表和版本信息，但不提供历史重算按钮、预览按钮或后台全量扫描状态。

### 5.3 导出

在价格设置区域提供：

- **“导出当前价格”**：导出包含当前所有模型版本、provider、匹配字段、生效时间和字段版本的完整 JSON；导出不包含 token、会话标题、路径等隐私数据。
- 文件名建议：`codex-usage-hud-pricing-YYYYMMDD-HHmm.json`。
- 导出内容必须可直接再次导入，保留未知字段时给出兼容提示或安全忽略。

### 5.4 空模板

提供 **“下载空价格模板”**，模板包含：

- 顶层 `schema_version`、`unit`、`prices`。
- 一条完整注释/示例结构（如 JSON 不支持注释，则使用 `__说明` 字段或随模板提供说明文本）。
- 所有支持字段：`model`、`provider`、`base_url`、`input`、`cached_input`、`cache_write`、`output`、`reasoning`、`effective_at`。
- `prices` 默认空数组，不带任何实际价格，避免用户误把示例当真实价格。
- 同时提供“复制示例”按钮，复制最小合法条目。

### 5.5 导入

- 支持文件选择和粘贴 JSON 两种方式。
- 导入先解析、校验、去重并展示预览，用户确认后才写入。
- 默认导入策略：按条目 `effective_at` 新增版本；相同匹配范围和时间的条目显示冲突并要求选择覆盖或取消。
- 导入失败必须原子回滚，现有价格、版本和生效时间不变。
- 导入成功提示新增/更新/跳过数量，并显示最近一次导入时间。

## 6. 数据与兼容迁移

- 为现有单价配置生成一个 `builtin_migration` 版本，`effective_at` 使用迁移时刻；不为现有普通会话补建全量价格快照。
- 对已有普通会话记录：保持现有缓存和已展示结果；只有后续发生文件变化时，新增请求才进入正常计价流程。
- 对已有后台请求：保留用量数据库中的费用、价格状态和版本字段，保证旧聚合结果可读；历史重算表不再写入。
- 如果用户已有 `pricing-snapshots.sqlite3`，只停止使用，不自动删除用户文件，避免无授权的数据删除。
- 现有 `pricing_url` 保留，但更名/辅助说明为 **“价格 JSON 获取地址（可选）”**；它只是用户自定义导入来源，不是官方认证地址。
- `ModelPrice.to_dict()` 的旧字段继续可读；新字段缺省时按当前迁移规则补齐。

## 7. 错误、回退与安全

- 导出失败：不改变配置，提示本地文件写入错误。
- 导入 JSON 非对象、价格非数字、负数、NaN/Infinity、缺少模型或 input/output：拒绝整个导入。
- 导入地址仅允许 HTTP(S)；限制响应大小和超时时间；不执行返回内容中的代码。
- 任何网络获取失败都不覆盖最近成功的本地价格版本。
- 价格金额使用 Decimal 或等价精确表示，最终展示按现有 HUD 精度格式化。

## 8. 验收标准

### 生效时间

- 修改价格并确认，服务端记录保存确认时刻，弹窗不要求用户填写生效时间。
- 保存新价格不触发普通会话历史扫描、影响预览、汇总缓存重建或后台全量扫描。
- 修改价格后刷新 HUD，已有缓存结果保持不变；保存之后产生的新请求按新版本计价。
- 新版本匹配不到时明确显示 `fallback`/`unavailable`，不显示为 `$0`。
- provider、base URL、模型别名同时存在时，匹配优先级和版本选择可由测试固定。

### 导入导出模板

- 导出 JSON 可以无损导入，模型匹配、缓存价格和生效时间保持一致。
- 空模板无需用户猜字段即可填写并通过校验。
- 非法导入不会改变任何原配置。
- 导入冲突有预览和明确处理结果。

### 回归与兼容

- 现有 `hud_settings.json` 可加载；旧格式价格仍可读。
- Renderer 设置页完成全部流程；不新增 Qt/Tk 行为。
- 普通会话、CLI、后台用量的 token 总数不变；改价不改写已有历史费用。
- 运行时不创建、读取或写入普通会话的 `pricing-snapshots.sqlite3`；旧文件保持不动。
- 历史重算命令、影响预览命令和 Renderer 入口不存在；旧后台重算表只保留兼容结构。
- 单元测试覆盖边界时间、时区、迁移、导入导出、冲突、回退和“保存不扫描历史”。
- `python -m pytest -q`、`python -m compileall -q src tests tools`、`git diff --check` 通过。

## 9. 实现与验证映射

2. `core/calculator.py`：按 provider、base URL、模型匹配优先级选择 `occurred_at` 对应版本，并输出 `fallback`/`unavailable` 状态。

4. `core/background_usage.py`、`background_usage_runtime.py`：后台新请求按请求时间计价并保存自身聚合所需的费用元数据；历史重算 API 已移除，旧表结构仅兼容保留。
5. `runtime_commands.py`、`settings_bridge.py`：设置命令、导入导出、模板和价格变更审计；不提供影响预览或历史重算命令。
6. `renderer_assets/settings_shell.py`、`router.py`、`layout_style.py`：保存新价格提示、导入冲突取消/覆盖、文件导入和下载；不包含历史重算入口。
7. `tests/test_calculator.py`、`test_config.py`、`test_parser.py`、`test_background_usage.py`、`test_pricing_runtime_commands.py`、Renderer 契约测试：覆盖边界时间、迁移、导入导出、冲突、回退、原子性以及“旧命令和入口已移除”。

## 10. 已决策产品规则

- 不允许未来预约调价；`effective_at` 必须带时区且不得晚于确认时刻。
- provider 是计费边界；同一模型在不同 provider 或 base URL 下不共用价格版本。
- 普通手工改价的 `effective_at` 由确认保存时生成；新价格只影响该时刻之后产生的请求。
- 保存价格永远不触发历史重算、影响预览、普通会话全量快照或汇总缓存重建。
- `pricing_audit` 只保留价格版本变更记录，满足“我什么时候改过什么价格”的追溯需求；不承担历史费用审计。
- 不提供历史费用重算能力；已有后台重算表/字段只为读取旧数据库而保留，不再有产品入口或运行时写入。
