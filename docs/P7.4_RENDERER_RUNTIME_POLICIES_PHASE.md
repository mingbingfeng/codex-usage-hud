# P7.4 Renderer Runtime Policies Phase

- Date: 2026-08-03
- Scope: renderer refresh/invalidation policies and stateless adapters
- Status: implementation and focused automated evidence complete

## Result

`renderer_runtime_policies.py` is now the terminal owner for renderer-specific
refresh and invalidation decisions: failure/backoff classification, CDP port
parsing, JSON/path signatures, budget/session invalidation, visible-first
session selection, active-work refresh, and event-driven idle-wait decisions.
These functions only inspect passed state and delegate pure policy decisions;
they do not construct or close resources, start workers, or push CDP payloads.

The two side-effecting adapters remain in `renderer_runtime.py` by design:
`_refresh_renderer_cdp_dependents` refreshes an existing platform probe, and
`_invalidate_active_session_mapping_cache` mutates the existing tracker. The
renderer runtime imports the new policy symbols explicitly as compatibility
aliases. `runtime_compat` and session-port materialization resolve these names
from the new owner first, while old `runtime_orchestration` private paths remain
available.
