# 后台用量 HUD 交互与加载修复

## Goal

修复 Codex App 后台用量气泡和设置页的五项体验问题：跳转后可靠恢复并置前 Codex App、后台用量提醒始终保持方形、设置页快速且不会无限加载、历史与详情滚动位置在交互刷新中保持稳定，并确保后台提醒绝不挤掉当前正在运行的真实任务气泡。

## Background

- 后台用量气泡点击目前只写入 `openBackgroundUsage` 命令；会话气泡已有的 Codex 窗口恢复/置前路径没有被调用，因此最小化后的 App 不会给用户可见反馈（`src/codex_usage_hud/cli.py:3809`）。
- 后台用量当前投影为 `status="background_usage"`，但完成态判定只检查 `status="recent"`，没有把 `kind="background_usage"` 固化为永不进入圆形完成态的产品约束（`src/codex_usage_hud/ui/work_overlay_qt.py:234`）。
- 气泡跳转先调用 `renderSettingsModal("backgroundUsage")`，该函数会自动发起一次查询，随后跳转分支又显式发起第二次查询。旧请求的响应因 request ID 不匹配被忽略后，又会从通用刷新分支发起下一次查询，形成持续追逐并一直显示“正在读取后台用量...”的循环（`src/codex_usage_hud/ui/renderer_hud.py:5605`, `src/codex_usage_hud/ui/renderer_hud.py:5723`, `src/codex_usage_hud/ui/renderer_hud.py:9115`）。
- 2026-07-20 的真实 renderer DOM 证据为 `aria-busy=true`、0 个事件行，且仍显示加载文案；同一时段日志记录了 `backgroundUsage` 单域更新超时后恢复。HUD 自有数据库有 67 个后台事件、301 个请求，事件列表查询 8 次的平均耗时约 1.8 ms，因此瓶颈不在 SQLite 查询或当天数据量。
- 设置页每次列表、详情或 Prompt 状态变化都执行 `body.innerHTML = backgroundUsagePanelHtml()`，历史区和详情区的滚动容器随 DOM 一起重建，滚动位置必然归零（`src/codex_usage_hud/ui/renderer_hud.py:5554`）。
- 当前 `_ordered_overlay_items()` 固定返回“后台用量、已完成会话、活动会话”，随后 `_visible_overlay_items()` 直接截取前 `item_limit` 项（`src/codex_usage_hud/ui/work_overlay_qt.py:927`, `src/codex_usage_hud/ui/work_overlay_qt.py:1104`）。真实 overlay 状态有 8 项、上限为 6，两个后台提醒和四个已完成会话占满前六位，`current=true` 的真实任务排在第七位而不可见；现有测试还把后台提醒抢占唯一槽位写成了预期（`tests/test_ui.py:4709`）。

## Requirements

### R1. 气泡跳转恢复并置前 Codex App

- 点击后台用量气泡底部链接后，先把目标事件排入 renderer 设置命令，再复用现有跨平台窗口恢复/置前能力。
- Windows 上最小化的 Codex App 必须被恢复并置前；macOS 继续使用现有 App 激活路径。
- 跳转仍只打开“后台用量”Tab 并选中对应事件，不切换会话、不自动确认事件。
- 窗口恢复失败为可诊断的 best-effort 失败，不得阻止已经排队的设置页跳转。

### R2. 后台用量气泡只使用方形态

- `background_usage` 项无论后续状态字段如何变化，都不得被完成态判定、布局或过渡逻辑归入圆形徽章。
- 后台用量提醒保持方形卡片，直到用户确认后直接移除；不得播放会话完成态的方形转圆形动画。
- 混合列表重绘必须按稳定 item ID 更新既有 widget；后台卡片不得借用普通会话的圆形 widget，完成会话也不得借用后台项的方形 widget。
- 普通会话的现有方形活动态、圆形完成态和交互保持不变。

### R3. 后台用量首屏快速且有界

- 一次打开动作只允许有一个有效的列表查询；重复打开或旧响应不得触发新的查询追逐。
- 气泡跳转的第一次成功响应直接包含当天列表、指定事件以及不含 Prompt 的详情预览；普通打开则在第一次成功响应中选择最近事件并提供同样的详情预览。
- 请求明细和归因信息随详情预览可见；Prompt 仍只能通过选中事件的详情响应按需取得，不能进入普通 HUD payload 或列表响应。
- 查询/详情响应只消费与当前 request ID 和当前事件匹配的数据；陈旧响应直接丢弃。
- renderer 确认接收一次性后台用量响应后，Python 才清除该响应；发送失败时保留以供重试。
- 查询在有界时间内没有响应时停止加载态，显示可重试错误，不得无限显示“正在读取后台用量...”。

### R4. 滚动位置稳定

- 历史列表在选择事件、详情返回、Prompt 展开/收起以及同 revision 重绘时保持原滚动位置。
- 详情区按 `eventId` 保存滚动位置；同一事件异步更新不跳顶，返回已查看事件时恢复其位置，新事件首次打开从顶部开始。
- 日期范围或筛选条件改变时可以按新结果集重置到顶部，不得把旧结果的滚动位置错误套到新结果。
- 窄屏单列布局同时保护设置 body 的滚动位置。

### R5. 当前真实任务气泡优先可见

- “Codex App 后台任务使用了额度”只能占用当前真实任务之外的剩余展示槽位，不得让当前正在运行的任务线程气泡消失。
- 即使 `work_overlay_max_items` 只允许显示一个气泡，只要当前真实任务存在，该槽位也必须留给当前真实任务。
- 后台用量提醒仍应在有剩余槽位时显示，且不得通过叠放或相同坐标遮住当前任务。
- 可见优先级为：当前活动任务、后台用量提醒、已完成会话、其他活动会话；各分组继续沿用自身现有时间排序。
- 没有当前活动任务时，后台提醒、已完成会话和其他活动会话的相对规则保持不变。

### R6. 兼容性与范围

- 保持 renderer mode 为设置页唯一产品路径；只对现有 PySide6 工作气泡 helper 做必要维护。
- 不改变后台用量识别、费用估算、确认持久化、会话用量聚合或 Provider 统计。
- 不新增轮询；加载超时只使用每次请求对应的有界 timer。
- Windows 与 macOS 的现有窗口激活语义均需保留。

## Acceptance Criteria

- [x] 最小化 Codex App 后真实点击后台用量气泡链接，App 被恢复并置前，设置页打开“后台用量”Tab 且选中正确 `eventId`。
- [x] 窗口激活失败时跳转命令仍会执行，并在日志/事件上下文中记录窗口恢复结果。
- [x] `background_usage` 即使带有 `status="recent"` 也仍按方形卡片处理，不产生 `card_to_completed` 或圆形徽章。
- [x] 三条后台提醒与普通完成/活动会话并存并重复刷新时，后台标题只出现在方形卡片，完成会话标题只出现在圆形徽章，活动会话保持方形。
- [x] 气泡跳转只提交一个首屏查询；普通 Tab 打开只提交一个首屏查询；陈旧响应不会再触发查询。
- [x] 首个有效响应后立即出现列表和指定/最近事件的详情预览，不再停留在无限加载态。
- [x] 查询超时会显示明确错误和刷新入口；后续成功刷新可恢复页面。
- [x] 列表/普通 payload 不含 Prompt；选中事件的详情路径仍可读取并安全显示 Prompt。
- [x] 历史列表在选择第 N 项后保持原滚动位置；详情异步返回和 Prompt 切换保持该事件的滚动位置；切回已查看事件可恢复其位置。
- [x] 当当前真实任务与后台用量提醒同时存在时，当前任务始终可见；展示上限为 1 时只显示当前任务，有额外槽位时才显示后台提醒。
- [x] 后台用量聚焦测试、完整测试、编译检查和 diff 检查通过。
- [x] 真实 Codex App/HUD 验证包含 DOM 状态、滚动位置、窗口最小化/恢复、helper 命令和 renderer 日志证据。

## Future Product Note: 替换“存储”Tab（不属于本任务）

- 用户明确认为当前“存储”页实用性不足，希望把该一级入口改造成面向日常用户的实用功能；具体方向尚未确定。
- 当前页面本质是手动触发的 Codex 私有目录 inventory / 清理器：展示路径元数据、风险分类、dry-run 与二次确认。raw 清理仅允许超过 7 天、未被配置引用且名称可识别的 `.tmp` staging/clone；会话、插件和登录只能调用官方 Codex 动作，其余大量 SQLite、配置、运行时和未知项只展示为受保护。
- 该能力安全边界强但高频收益低，而且在一级设置导航中占用显著位置。候选替代方向必须保持 renderer-only、local-first、无遥测，并优先复用已有会话、token、费用、缓存、Provider、模型和后台用量数据。
- 当前最高价值待决策：新 Tab 首先服务于“用量洞察与异常定位”、“会话管理”，还是“运行健康诊断”。方向确认前不确定信息架构、数据合同或是否拆成独立可验收子范围。
- 本节仅保留并发发现的未来产品意图，不构成本任务开放问题、需求或验收条件；后续如要实施，应单独获得任务创建与规划授权。

## Out Of Scope

- 修改后台任务识别规则、扫描游标、价格估算或历史数据库结构。
- 将后台用量并入会话、日预算或周预算统计。
- 重做设置页视觉样式、普通会话气泡或已弃用的 Qt/Tk HUD 产品界面。
- 替换或重做“存储”Tab。
- 新增 Provider/中转站账单访问或网络依赖。
