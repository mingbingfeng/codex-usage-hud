# 空间清理与会话删除改版提案（已确认）

> 状态：用户已于 2026-07-21 确认 V1 设计。实现和验证不得对用户真实会话执行删除。

## 目标

- 一级设置入口从“用量洞察”改为“空间清理”，页面只处理本地清理和会话管理。
- 默认垃圾清理缩成两个显式动作：`扫描垃圾` -> `确认清理`。
- 增加“会话管理”，支持永久删除 Codex App 只能在界面中归档的会话。
- 保留现有 inventory revision、opaque ID、路径边界、指纹、进程门禁、SQLite 备份和恢复合同。

## 已确认事实

- 用量排行已经迁移到“用量总览”，清理页不再需要保留用量洞察上半部分。
- 当前清理 UI 把三层摘要、分组、确认项、备份目录、自动关闭和显式预览同时铺开，默认路径需要扫描、生成预览、再次确认三个主要动作。
- 本机 `codex-cli 0.144.6` 已提供 `codex delete --force <UUID>`。
- 对应的官方 `thread/delete` 实现会删除 active/archived rollout、会话名称索引、状态库记录，并按 spawn tree 先删除子 agent 后删除主会话。
- 现有 `CodexFileManager` 虽已有 `delete_session` 动作，但当前拼出的命令缺少 `--force`，在 `stdin=DEVNULL` 下不能作为 HUD 的非交互删除合同直接复用。

## 信息架构

一级入口：`空间清理`

页内分段：

1. `垃圾清理`
   - 扫描前
   - 扫描结果 / 默认安全选择
   - 可选“深度清理”折叠区
   - 执行结果
2. `会话管理`
   - 搜索、状态筛选、最后活动时间筛选
   - 主会话列表；子 agent 折叠归属于主会话
   - 批量永久删除
   - 删除结果

## 两步垃圾清理合同

1. 用户点击“扫描垃圾”。
2. 后端完成 inventory 后，自动为默认 `safe` 选择生成 preview 和单次 confirmation token。
3. UI 直接把这个 preview 渲染成扫描结果，不再暴露“生成清理预览”按钮。
4. 用户点击“确认清理”，执行 token 绑定的 revision 和选择。
5. 如果用户展开并修改“深度清理”、保留期或备份目录，后台静默重建 preview；按钮在新 token 返回前保持禁用。

默认结果只展示真正可操作的垃圾分类。受保护空间收口为一行摘要，不把配置、会话、活动缓存伪装成“垃圾”。SQLite 历史仍默认不选中，只有打开“深度清理”后才显示保留期、备份目录和关闭/恢复影响。

## 永久删除会话合同

- 会话列表只展示标题、工作目录尾部、最后活动、状态、占用和关联子任务数，不传 prompt/response。
- 删除选择使用扫描 revision + opaque item ID；canonical UUID 只保留在 Python 端。
- 当前会话、运行中的会话、活动子 agent、临时未持久化会话、canonical UUID 不明的会话不可选择。
- 子 agent 不作为重复顶层行；主会话行显示“含 N 个关联子任务”。删除主会话时确认摘要必须包含这些后代。
- 执行使用 `codex delete --force <canonical UUID>`，不直接删除 rollout 或手写 `state_5.sqlite`。
- HUD 启动时探测 delete capability。命令不可用时禁用永久删除，不降级为 raw 文件删除。
- 批量删除逐个主会话执行；每项执行后重新核对 rollout、会话索引和 state DB。部分失败按会话报告，不把整批显示为成功。
- 永久删除不创建恢复备份；选择、删除按钮和最终确认构成独立的强确认流程。

## 视觉方案

- 延续 Codex 设置弹窗的紧凑深色工具风格，沿用现有尺寸和顶部导航。
- “扫描垃圾”是扫描前唯一主按钮；结果页底部只有“重新扫描”和“确认清理”。
- 安全清理用绿色状态，深度清理用黄色状态，永久删除只在最终动作使用红色。
- 列表使用整行分隔，不新增嵌套卡片；动态金额、数量和按钮区域使用稳定列宽。
- 设计稿：`docs/designs/space-cleanup-session-delete-v1.html` 与同名 PNG。
