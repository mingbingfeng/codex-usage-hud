二、两个根因Root causes, verified on real data

根因 1 · shell 启动器识别用了「完整路径」比对裸名

src/codex_usage_hud/core/parser.py:169-173 — _shell_launcher()
def _shell_launcher(value: str) -> bool:
    name = str(value or "").strip().casefold()
    if name.endswith(".exe"):
        name = name[: -len(".exe")]
    return name in _SHELL_LAUNCHERS   # ← 集合里是 "pwsh"，这里传进来是 "d:\...\7\pwsh"

实测：_shell_launcher(r"D:\Program Files\PowerShell\7\pwsh.exe") → 去 .exe 得 d:\program files\powershell\7\pwsh → 不在 _SHELL_LAUNCHERS（集合内为裸名 pwsh / bash …）→ 返回 False。 于是 _normalise_command_parts 的剥离分支被整个跳过，左下角原样吐出： 

# 左下角现在实际显示（status_label，单行，最窄约 206px）
D:\Program Files\PowerShell\7\pwsh.exe -Command git status --s…
# 真正该显示的（来自 parsed_cmd[0].cmd，100% 覆盖）
git status --short --branch

根因 2 · compact_text 把换行压成空格，「三行细节」无从谈起

src/codex_usage_hud/core/parser.py:52-59 — compact_text()
def compact_text(value: Any, limit: int = 140) -> str:
    if value is None: return ""
    text = re.sub(r"\s+", " ", str(value)).strip()   # ← \r\n 也被压成空格

activity_steps 在 parser.py:2530-2535 与 2572-2575 用 compact_text(…, 220) 存 output。结果是「从开头截取的 220 字符、没有换行」的一坨文本 —— 既拿不到最新进展，也没有行结构。真实对比：

# 期望：保留换行的尾部 3 行（最新进展，信息密度最高）
